## 1. 本書について

### 1.1 目的

要件定義書 8 章の機能一覧にある機能ごとに、「利用者が何をできるか（機能要件）」と「そのためにアプリが何をするか（処理・入力の確認・API・データ・エラー）」を 1 つの文書にまとめる。1 つの機能を作るときに、その機能の文書を読めば作れるようにする。

### 1.2 機能定義書の構成

機能定義書は、本書（全機能に共通の決まり）と、次の機能ごとの文書でできている。

### 1.3 機能ごとの文書の章立て

機能ごとの文書は、すべて次の章立てにする。その機能に当てはまらない章は「なし」と書く。

| 章 | 内容 |
| --- | --- |
| 1. 概要 | 目的、使う画面、関係する機能、前提 |
| 2. 機能要件 | 利用者ができること（要件 ID つき）。検収はこの章の ID ごとに行う |
| 3. 処理の流れ | 画面・API・データベース・S3 の間で何が起きるか（Mermaid の図） |
| 4. 入力の確認 | 入力項目ごとの条件と、守られないときのメッセージ |
| 5. 業務ルール | 状態の変わり方、件数・並び順の決まりなど |
| 6. API（案） | URL・メソッド・入力・出力・HTTP ステータス。3 章の共通の決まりに従う |
| 7. 使うデータ | 読み書きするテーブルと、その操作（CRUD） |
| 8. 権限 | 誰が何をできるか |
| 9. エラーとメッセージ | 起きうるエラーと、画面に出すメッセージ・HTTP ステータス |
| 10. テストの観点 | テスト仕様書を作るときに必ず確かめること |

画面の見た目は[画面設計書](../design/screen-design.md)に、テーブルの定義は[データ設計書](../design/data-design.md)に書き、機能定義書には書かない（同じ内容を 2 か所に書かない）。

## 2. 共通の決まり（画面）

- 用語（トリム、文字数、第三者など）は要件定義書 5 章のとおり
- 「誰でも見られる」は、ログインしているユーザーなら誰でも、という意味である。ログインしていない人は何も見られない（N-10）
- 入力の共通ルール（トリム、Enter キーの扱い、上限を超えた入力）は画面設計書 3.8 のとおり
- いいね・フォロー・コメント・削除・保存に失敗したときは、画面をその操作の前の状態に戻して M-18 を出す
- インターネットに接続できないことに気づいたら M-20 を出し、接続が戻ったら消す
- API が 401 TOKEN_EXPIRED を返した（JWT の期限が切れた）ときは、画面は利用者に知らせずに POST /api/auth/refresh で JWT を取り直し、元の操作を 1 回だけやり直す。取り直しにも失敗した（ログインの期限が切れていた）ときは、M-19 を出して G-1 に移す（A-8）

## 3. 共通の決まり（API）

### 3.1 基本

| 項目 | 決まり |
| --- | --- |
| URL | すべて /api で始める。画面の URL（/posts/1 など）と分ける |
| 形式 | 入力・出力とも JSON（UTF-8）。画像を送るときだけ multipart/form-data |
| ID | 数値（bigint）。JavaScript で扱える範囲（2 の 53 乗未満）に収まる |
| ユーザーの指定 | URL ではユーザー ID（username）で指定する。大文字・小文字は区別しない |
| 日時 | ISO 8601 形式の UTC（例：2026-10-16T06:30:00Z）。画面で日本時間に直す |
| 文字列 | サーバー側でもトリムし、文字数をコードポイントで数えて確かめる（画面の確認だけに頼らない） |

### 3.2 ログイン（JWT 認証）と CSRF 対策

ログインの状態はサーバーに覚えさせず（セッションを使わない）、JWT で確かめる（N-25）。流れは FN-01 の 3 章のとおり。

| 項目 | 決まり |
| --- | --- |
| アクセストークン | JWT。署名は HS256（秘密の値は Parameter Store。N-16）。中身は sub（ユーザーの ID）・username・iat（発行時刻）・exp（期限）。有効期限 15 分 |
| リフレッシュトークン | 推測できない 32 バイトの乱数を文字列にしたもの（JWT ではない）。有効期限 14 日。データベースには SHA-256 のハッシュだけを保存する（データ設計書 4.7） |
| 渡し方 | どちらも Cookie（HttpOnly・SameSite=Lax、公開時は Secure）で渡す。アクセストークンは `access_token`（Path=/api）、リフレッシュトークンは `refresh_token`（Path=/api/auth。refresh と logout のときだけ送られる）。画面の JavaScript からは読めない。Authorization ヘッダーは使わない |
| 確かめ方 | Spring Security の OAuth2 Resource Server の JWT の確認を使い、Cookie の access_token を読む。署名・期限が正しければ、データベースを読まずに sub の人としてログイン済みにする |
| ログインしたままにする | アクセストークンの期限が切れたら、POST /api/auth/refresh で両方を新しくする（2 章）。リフレッシュトークンは使うたびに新しいものに替えるので、最後の操作から 14 日たつまでログインしたままになる（A-8） |
| ログアウト | リフレッシュトークンをデータベースで無効にし、両方の Cookie を消す。すでに渡したアクセストークンは、Cookie を消すため使われなくなる（最長 15 分は署名としては有効のまま） |
| CSRF | Cookie は自動で送られるため、CSRF 対策は続けて行う。Cookie（XSRF-TOKEN）に入れたトークンを、画面が X-XSRF-TOKEN ヘッダーで送り返す。GET 以外のすべての API で確かめる。トークンを新しくするのはログイン・登録のときだけ（ログインの前に仕込まれたトークンを使わせない）で、ログインした後の API では変えない（変えると、読み込みの途中に送った操作のトークンが合わなくなる） |
| ログインがいらない API | POST /api/auth/signup、POST /api/auth/login、POST /api/auth/refresh、GET /api/auth/username-availability だけ。それ以外はアクセストークンがなければ 401 |

### 3.3 エラーの形

エラーのときは、HTTP ステータスと次の JSON を返す。画面は message をそのまま出し、field があればその入力欄の下に出す。

```json
{
  "code": "USERNAME_TAKEN",
  "message": "このユーザー ID は使われています。",
  "field": "username"
}
```

| HTTP ステータス | 使うとき |
| --- | --- |
| 400 | 入力が条件に合わない（code は各機能定義書の 9 章）。画面を通さずに送られた入力（JSON が読めない、画面では入力できない長さなど）は、code を BAD_REQUEST、message を「入力が正しくありません。」にする |
| 401 | ログインしていない（UNAUTHENTICATED）、アクセストークンの期限切れ（TOKEN_EXPIRED。画面は取り直してやり直す）、リフレッシュトークンが使えない（REFRESH_FAILED） |
| 403 | 権限がない（他人の投稿の削除など）、CSRF トークンが合わない |
| 404 | 投稿・ユーザーなどが存在しない |
| 409 | 重複（使われているユーザー ID） |
| 413 | 画像（投稿の画像・アイコン）が大きすぎる |
| 423 | ログインの失敗が続いて、ログインできない（A-7） |
| 500 | サーバーの中の失敗（S3・データベースの障害など）。message は M-14 か M-18 |

### 3.4 一覧の読み込み（ページング）

| 項目 | 決まり |
| --- | --- |
| 方法 | カーソル方式。前回の出力の nextCursor を、次の入力の cursor にそのまま渡す。最後まで読んだら nextCursor は null |
| 件数 | タイムライン・投稿・いいね・フォローの一覧は 20 件、コメントは 50 件 |
| カーソルの中身 | 新しい順の一覧は「最後に出した行の ID」、日時順の一覧は「最後に出した行の日時と ID」を文字列にしたもの。画面はカーソルの中身を読まない |
| 例外 | ユーザー検索だけは並び順が検索語で変わるため、件数（offset）で指定する（FN-08） |

一覧を返す API の出力は、すべて次の形にする。

```json
{
  "items": [ … ],
  "nextCursor": "1234"
}
```

### 3.5 よく使う出力の形

#### 投稿（PostView）

```json
{
  "id": 1234,
  "author": { "username": "taro_y", "displayName": "たろう", "iconUrl": null },
  "body": "今日は晴れ。川沿いを散歩してきた",
  "images": [
    { "id": 55, "url": "https://…（署名付き URL）", "expiresAt": "2026-10-16T06:45:00Z" }
  ],
  "likeCount": 12,
  "commentCount": 3,
  "likedByMe": true,
  "mine": false,
  "createdAt": "2026-10-16T06:30:00Z",
  "editedAt": null
}
```

- インプレッション数・リツイート数の項目は持たない
- editedAt は最後に本文を編集した日時。編集していなければ null（W-11）
- author は投稿者。コメント（FN-05）の author も同じ形にする。iconUrl はアイコン画像の署名付き URL（15 分有効）で、アイコンを設定していなければ null（PF-10）

#### ユーザー（UserSummary）

```json
{
  "username": "taro_y",
  "displayName": "たろう",
  "bioFirstLine": "川沿いを散歩するのが好きです",
  "iconUrl": null,
  "followedByMe": false,
  "me": false
}
```
